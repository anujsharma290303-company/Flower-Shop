## 📏 PART 4: FRONTEND RULES & CONSTRAINTS

### 4.1 Mandatory Rules

**MUST DO:**
- ✅ Use Tailwind CSS for **all** styling (NO custom CSS initially)
- ✅ Use TypeScript for **all** components (NO `.js` files)
- ✅ Create `.tsx` files (React + TypeScript)
- ✅ Use functional components with hooks only
- ✅ Separate concerns: components, hooks, utilities, types
- ✅ Version control: Commit after each major component
- ✅ Responsive design: Mobile-first approach
- ✅ Semantic HTML: Proper heading hierarchy, alt text
- ✅ Error handling: Try/catch for API calls
- ✅ Loading states: Show spinners during data fetch

**MUST NOT DO:**
- ❌ NO class components (only functional)
- ❌ NO custom CSS files (use Tailwind)
- ❌ NO hardcoded strings (use constants)
- ❌ NO API calls in components (use hooks/services)
- ❌ NO missing TypeScript types
- ❌ NO inline styles
- ❌ NO nested ternaries (keep JSX clean)
- ❌ NO direct DOM manipulation
- ❌ NO global state for simple props
- ❌ NO console.logs in production code

### 6.2 Component Template

```typescript
// Standard component structure
import React from 'react'
import { ComponentProps } from '@/types/components'

// 1. Define props interface
interface YourComponentProps {
  label: string
  onClick?: () => void
  variant?: 'primary' | 'secondary'
  disabled?: boolean
  className?: string
}

// 2. Component definition
const YourComponent: React.FC<YourComponentProps> = ({
  label,
  onClick,
  variant = 'primary',
  disabled = false,
  className
}) => {
  // 3. State & effects here
  
  // 4. Handlers here
  
  // 5. Render
  return (
    <button
      onClick={onClick}
      disabled={disabled}
      className={cn(
        // Base styles
        'px-4 py-2 rounded transition-all',
        // Variant styles
        variant === 'primary' && 'bg-red-600 text-white hover:bg-red-700',
        variant === 'secondary' && 'bg-gray-200 text-gray-900 hover:bg-gray-300',
        // State styles
        disabled && 'opacity-50 cursor-not-allowed',
        // Custom classes
        className
      )}
    >
      {label}
    </button>
  )
}

// 6. Export with display name
YourComponent.displayName = 'YourComponent'
export default YourComponent
```

### 6.3 Props Patterns

**NEVER DO THIS:**
```typescript
// ❌ BAD: Prop spreading can hide dependencies
const Component = (props: any) => <div {...props} />

// ❌ BAD: Missing types
const Button = ({ label, onClick }) => <button>{label}</button>

// ❌ BAD: Too many props
const Card = ({ a, b, c, d, e, f, g, h }) => {}
```

**DO THIS INSTEAD:**
```typescript
// ✅ GOOD: Explicit props with types
interface ButtonProps {
  label: string
  onClick: () => void
  variant?: 'primary' | 'secondary'
}

const Button: React.FC<ButtonProps> = ({ label, onClick, variant = 'primary' }) => {
  // implementation
}

// ✅ GOOD: Use composition for complex layouts
interface CardProps {
  header: React.ReactNode
  body: React.ReactNode
  footer?: React.ReactNode
}
```

## ⚡ PART 8: INTERACTION & BEHAVIOR PATTERNS

### 8.1 Button Interactions

**ALL buttons must have:**
- ✅ Hover state (color change or scale)
- ✅ Active state (visual feedback)
- ✅ Disabled state (grayed out, cursor not-allowed)
- ✅ Smooth transitions (200ms)
- ✅ No console warnings

**Click handlers:**
```typescript
const handleClick = async () => {
  try {
    // Action here
  } catch (error) {
    // Error handling
  }
}
```

### 8.2 Navigation Behavior

```
Navigation bar:
├── Always visible (sticky on scroll)
├── Logo clickable (navigates home)
├── Active link highlighted
├── Mobile: hamburger menu (collapsible)
├── Cart updates in real-time
└── User menu shows on hover/click

Transitions:
├── Page load: subtle fade-in
├── Link hover: color transition (200ms)
├── Menu open: slide-down animation (300ms)
└── Page change: smooth scroll to top
```

### 8.3 Loading States

```
All API calls must show:
├── Loading skeleton or spinner
├── Disabled state for buttons
├── "Loading..." text if space allows
├── Maintain layout to prevent shift
└── Error state with retry option

Pattern:
if (loading) return <Skeleton />
if (error) return <ErrorMessage retry={retry} />
return <Content />
```

### 8.4 Form Interactions

```
Input fields:
├── Real-time validation (show errors immediately)
├── Visual feedback on focus
├── Error message below field
├── Success checkmark when valid
└── Submit button enables only when valid

Validation:
├── Email: RFC 5322 standard
├── Password: min 8 chars, 1 uppercase, 1 number
├── Phone: valid US format
└── Custom validation as needed
```

## ✅ PART 9: DO's & DON'Ts

### 9.1 DO's

**✅ Architecture:**
- ✅ Keep components small and focused (single responsibility)
- ✅ Lift state up only when necessary
- ✅ Use context for cross-cutting concerns (auth, cart)
- ✅ Use hooks for reusable logic
- ✅ Create utilities for repeated functions

**✅ Styling:**
- ✅ Use Tailwind classes exclusively
- ✅ Use `cn()` utility for conditional classes
- ✅ Create Tailwind component classes for complex styles
- ✅ Follow mobile-first approach
- ✅ Test on all breakpoints

**✅ Performance:**
- ✅ Lazy load images with native `loading="lazy"`
- ✅ Memoize expensive components with `React.memo`
- ✅ Use `useCallback` for event handlers
- ✅ Code-split pages with React.lazy()
- ✅ Monitor bundle size

**✅ Accessibility:**
- ✅ All images have alt text
- ✅ All form inputs have labels
- ✅ All buttons have aria-labels if needed
- ✅ Color not only indicator of status
- ✅ Focus visible on interactive elements
- ✅ Semantic HTML (h1, h2, nav, button, etc.)

**✅ API Integration:**
- ✅ Use axios for all HTTP calls
- ✅ Centralize API calls in service files
- ✅ Handle 401 errors (redirect to login)
- ✅ Show user-friendly error messages
- ✅ Implement retry logic for failures

**✅ Types:**
- ✅ Type all props explicitly
- ✅ Use `React.FC<Props>` for components
- ✅ Import types from dedicated files
- ✅ Use `Omit`, `Pick`, `Partial` for type manipulation
- ✅ Never use `any` type

### 9.2 DON'ts

**❌ Architecture:**
- ❌ Don't create deeply nested folder structures
- ❌ Don't prop-drill more than 2 levels
- ❌ Don't use global state for component state
- ❌ Don't create components in pages directly
- ❌ Don't import from parent directories

**❌ Styling:**
- ❌ Don't use inline styles (`style={{}}`)
- ❌ Don't create custom CSS files for components
- ❌ Don't use !important in Tailwind
- ❌ Don't hardcode colors (use CSS variables)
- ❌ Don't skip responsive design

**❌ Performance:**
- ❌ Don't load all images upfront
- ❌ Don't create event handlers in render
- ❌ Don't use large dependencies without need
- ❌ Don't ignore bundle size warnings
- ❌ Don't render full lists without virtualization

**❌ Code Quality:**
- ❌ Don't leave console.logs in code
- ❌ Don't hardcode API URLs in components
- ❌ Don't skip error handling
- ❌ Don't create god components (too large)
- ❌ Don't repeat code (DRY principle)

**❌ Testing & QA:**
- ❌ Don't skip mobile testing
- ❌ Don't ignore accessibility warnings
- ❌ Don't deploy without manual testing
- ❌ Don't ignore TypeScript errors
- ❌ Don't skip network error scenarios

```typescript
// api/products.ts
import api from './axios'
import { Product, ProductListResponse } from '@/types/api'

export const productService = {
  // Get all products with optional filters
  async getAll(options: {
    category?: string
    limit?: number
    page?: number
    search?: string
  } = {}) {
    const response = await api.get<ProductListResponse>('/products', {
      params: options
    })
    return response.data
  },

  // Get single product
  async getById(id: number) {
    const response = await api.get<Product>(`/products/${id}`)
    return response.data
  },

  // Other methods...
}
```

### 11.2 Hook Pattern

```typescript
// hooks/useProducts.ts
import { useState, useEffect } from 'react'
import { productService } from '@/api/products'

export function useProducts(category?: string) {
  const [products, setProducts] = useState([])
  const [loading, setLoading] = useState(true)
  const [error, setError] = useState<string | null>(null)

  useEffect(() => {
    const fetchProducts = async () => {
      try {
        const data = await productService.getAll({ category })
        setProducts(data.items)
      } catch (err) {
        setError('Failed to load products')
      } finally {
        setLoading(false)
      }
    }
    fetchProducts()
  }, [category])

  return { products, loading, error }
}
```

### 11.3 Error Handling

```typescript
// All API calls must handle errors
try {
  const data = await api.get('/products')
  // Success handling
} catch (error) {
  if (axios.isAxiosError(error)) {
    if (error.response?.status === 401) {
      // Handle unauthorized
    } else if (error.response?.status === 404) {
      setError('Not found')
    } else {
      setError('Something went wrong')
    }
  }
}
```
